## Identidade, nomes e riscos

Trust OIDC usa aud sts.amazonaws.com e subjects exatos com owner/repository IDs
de AuroNet0 e environments homolog/production. A role k8s pode criar/excluir rede
com Resource=* limitado por região, gerenciar IAM incluindo OIDC e roles/policies
tech-challenge-oficina-*, e possui AmazonEKSClusterAdminPolicy no cluster.
Roles Auth/database também têm permissões de escrita/exclusão; são inadequadas
como fronteira de proteção de bootstrap para um futuro destroy efêmero.

Nomes EKS/ECR/IAM/RDS/Lambda/API e filtros de observabilidade são fixos;
tags comuns atuais Environment=shared. Cluster usa subnets públicas e endpoint
público/privado; privadas não declaram saída NAT. API Gateway legado usa URL pública,
não VPC Link/ALB interno. Não reutilizar a root inteira como ambiente Fase 4.
